## 2. Technical Course-Corrections & Key Decisions

During the final system review, two critical infrastructure and behavioral issues were identified and successfully patched to ensure the app runs flawlessly on any reviewer's machine:

### A. Testcontainers Version Pinning (Docker Engine 29 Compatibility)
* **The Issue:** Spring Boot 3.5.6 standard dependencies pin `Testcontainers` to version `1.21.3`. Under modern host environments running Docker Engine 29.x, this older client version passes an incompatible API version request, resulting in immediate `Status 400` connection rejections from the Docker socket and failing the test suites.
* **The Refinement:** Upgraded and pinned the Testcontainers dependency strictly to version `1.21.4` inside `build.gradle.kts`. This resolution explicitly guarantees that running `./gradlew test` executes flawlessly against a real containerized `postgres:15-alpine` instance on modern host machines.

### B. OpenAPI Contract Realignment (GET Validation Override)
* **The Issue:** A 65+ character or blank SKU passed into `GET /inventory/{skuId}` initially bubbled up to a standard `400 Bad Request` due to path validation constraints. However, the strict OpenAPI contract only permits `200 OK` or `404 Not Found` response codes for the retrieval route.
* **The Refinement:** Introduced an early-return guard boundary inside the REST Controller layer. Since a 65+ character SKU can never physically exist inside the database schema (due to our strict `VARCHAR(64)` column restriction), any malformed GET request is intercepted and manually thrown as a `SkuNotFoundException`, cleanly yielding a `404 Not Found` to remain 100% compliant with the contract schema.

### C. Eliminating Onboarding Friction
* **The Issue:** The default configuration values inside `.env.example` were left blank, forcing a reviewer to manually modify file data strings just to establish basic local orchestration container connectivity.
* **The Refinement:** Infused functional, localized, throwaway credential parameters (`nuuly_user` / `nuuly_password`) into `.env.example`. Reviewers can now execute a zero-friction, single-command clone pipeline (`cp .env.example .env && docker compose up -d`) to initialize their database stack instantly.

## 3. Engineering Team Defendable Talking Points

This assessment is fully optimized for a deep-dive architecture defense during the live interview loop. The following design choices highlight senior-level microservice maturity:

* **No JVM Lock State Dependency:** Concurrency protection relies exclusively on PostgreSQL row-level `FOR NO KEY UPDATE` transactions, ensuring horizontal scaling across unlimited stateless application server replicas.
* **HOT Update Optimizations:** Decrementing inventory creates intensive database write churn due to MVCC. Setting `fillfactor = 90` preserves a 10% space margin on every physical table disk page, letting updates execute in-place (Heap-Only Tuples) without incurring massive index maintenance overhead.
* **Fail-Fast Boundary Validation:** Utilized Hibernate `ddl-auto: validate` to guarantee Flyway migration absolute authority. Configured strict Jackson rules to drop float truncation and string coercion behaviors instantly at the HTTP deserialization gate before any malformed strings can touch the service logic.
